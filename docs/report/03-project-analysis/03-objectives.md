# 3.3 Project Objectives

## 3.3.1 General Objective

The general objective was to design and develop a simplified Electronic Medical Record application while experiencing the major stages of the software development lifecycle in an industrial internship environment.

## 3.3.2 Specific Objectives

The project objectives were to:

1. investigate healthcare workflows and established EMR concepts;
2. define a realistic internship-scale system scope;
3. document software requirements before implementation;
4. model the application's data and domain relationships;
5. design an appropriate application architecture;
6. implement patient-management functionality;
7. implement a longitudinal patient-chart model;
8. implement appointment scheduling and workflow;
9. implement authentication and role-based authorization;
10. preserve important history and audit information;
11. validate the application through automated and manual testing;
12. produce technical documentation and a user guide;
13. present and demonstrate the completed system;
14. develop practical understanding of industrial software-engineering processes.

## 3.3.3 Engineering Objectives

Beyond feature delivery, OCR had engineering objectives concerning:

- maintainability;
- separation of concerns;
- data integrity;
- role boundaries;
- predictable workflow transitions;
- validation;
- testability;
- documentation;
- traceability between requirements and implementation.

## 3.3.4 Learning Objectives

The internship also aimed to expose the intern to:

- requirements engineering;
- domain research;
- architecture;
- database design;
- full-stack development;
- Git/GitHub-based project organization;
- authentication and authorization;
- testing;
- technical writing;
- project communication;
- scope management;
- industrial collaboration.

## 3.3.5 Objective-to-Evidence Principle

Each objective should eventually be connected to evidence in the final report.

For example:

| Objective | Evidence |
|---|---|
| Research EMR workflows | Research log and methodology |
| Define requirements | SRS v2.0 |
| Model data | ERD/schema/migrations |
| Design architecture | Architecture documents and diagrams |
| Implement modules | Source code and UI evidence |
| Enforce access | Access-control documentation and tests |
| Test system | Automated tests and E2E checklist |
| Document system | Technical documentation/user guide |
| Present system | Final presentation materials |
| Learn industrial practice | Internship observations and reflection |

This traceability will be expanded in later chapters.
